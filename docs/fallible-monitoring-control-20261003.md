# Keep control workers alive when account monitoring is unavailable

The complete maker02 log from the superseded saturated-core deployment contained two unstructured panics: `poly-rtt-probe-join` near 19:55 UTC and `poly-safety-cancel-zhu02-0` near 20:00 UTC. Both unwound after the legacy `monitoring_snapshot()` RPC timed out waiting for the cold account owner. The safety-cancel worker count then fell from 12 to 11. Resource budgeting removes the observed saturation, but control callers must also handle the failure without terminating their long-lived worker.

`try_monitoring_snapshot()` preserves the existing owner-produced snapshot and reports timeout, full queue or disconnection as `Err`. The strict legacy wrapper remains available to startup/CLI/tests. Production full-RTT probes skip the optional probe on error. Retired-market cancellation disables its local-empty shortcut on unknown recovery state and continues authenticated cancellation/audit. Shutdown never declares a clean account from an unavailable snapshot. Unknown pending counts are explicit optional values, never zero. No stale monitoring snapshot is promoted into a risk or settlement authority.

This adds no mutable runtime field, queue, worker or thread-placement change. The account thread remains the sole writer. The existing bounded cold control RPC is unchanged in capacity, ordering and deadline; it is still a migration target for compact asynchronous owner evidence. This patch does not add a synchronous request to the quote path or broaden shared-account authority. Normal quote and order-dispatch behavior is unchanged.

Tests hold the cold owner past the deadline, consume the harmless late reply, then verify a subsequent request succeeds on the same owner. Full and disconnected lanes return errors while an independent account remains usable. Retired-market policy tests explicitly reject an unknown recovery count. The account and exchange regression suites cover the surrounding lifecycle, replay, overflow and routing paths.
