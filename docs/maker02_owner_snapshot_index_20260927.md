# maker02 私有所有者重复索引扩容长尾

前一轮完整 30 分钟总登记 P99 为 720.9 μs，仍未解决用户指出的 584 → 983 μs 回退。hexbot 已切换为保留 purge 的 Linux MADV_FREE 回收方式；16:21–16:36 UTC 的 15 分钟窗口总登记 P99/P999 降至 209.65/233.1 μs，但仍有 2620 μs 最大值。

新分段将该分钟的尖峰定位到 `identity_index`、`reverse_index`、`token_index`（最大 1630/2560/1670 μs），发布 CPU 最大 2590 μs，off_cpu 最大 1.5 μs。zhu02 启动恢复 28,330 条身份，旧代码将它们另行收集到三张平坦 HashMap，接近 28,672 条容量边界。源代码和容量边界基准确认整表扩容是可复现的毫秒级成本；现有分钟分位数不能证明每个具体实盘请求都恰好对应同一次扩容。

## 实现及所有权

`ExecutionStateOwner` 现在只持有当前 `ExecutionStateSnapshot`，由原私有所有者线程独占更新；移除三张重复身份 HashMap 及重复 open-order HashMap。更新直接查找/修改原不可变分层快照，在同一次提交中更新所有者当前代并向跨线程读者发布一致快照，旧读者继续持有旧代。

分块结算回收仍每轮最多检查 16 个 coid，并在所有者当前代重新核查 token 和反向 oid 归属，避免旧冷计划删除重绑定身份。兼容回收路径也读取当前代。没有新增线程、锁、消息或同步请求；现有生命周期队列的容量、优先级、排序、失败关闭及重放语义保持不变。

该变更消除历史总量级的重复可变表扩容及复制，不声称发布已零分配：分层叶节点/新身份仍有分配，ArcSwap 全局读者扫描仍存在。下一步迁移应采用所有者独占、有界的节点复用，保持旧代读者生命周期并量化容量耗尽回退，不能将无界释放队列引入热路径。原分段名保留用于纵向对照；identity/reverse/token_index 现在只包含查找、重绑定准备或阶段标记，不再写入平坦索引。

## 专项基准

命令：`CARGO_PROFILE_RELEASE_LTO=off CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16 cargo test --locked --release -p hexagent-exchange --lib benchmark_execution_owner_capacity_boundary -- --ignored --nocapture`。

macOS 默认测试分配器；N=128 次容量边界更新，三张旧表均在计时前填满至 28,672 条，前后交替测量。计时包含身份更新、快照构造、发布与旧发布代释放，输入和历史准备在外；旧读者始终持有原代。新路径包含新增分段观测，旧基线没有该观测。同步基准队列深度和溢出均为 0。

| 路径 | N | P50 ns | P99 ns | P999 ns | max ns |
|---|---:|---:|---:|---:|---:|
| 重复平坦索引扩容 + 发布 | 128 | 3,174,529 | 4,683,158 | 7,371,772 | 7,371,772 |
| 当前快照索引 + 发布 | 128 | 14,204 | 29,185 | 30,701 | 30,701 |

这是专门触发扩容的条件基准，不是整个工作负载的分位数，也不能替代 Linux/mimalloc 实盘端到端验收。

## 验证

新增测试覆盖连续更新、重复安装、重绑定后的旧证书、删除后重放、旧读者、独立所有者及三表一致发布；现有分块回收、生命周期顺序、溢出/关闭和重连测试继续执行。

第一次完整 release 测试 930 通过、2 失败，两项单独复跑均通过。失败的断言立即读取异步冷账本镜像；已有执行屏障只等待私有所有者，并非冷镜像屏障。测试夹具现在等待所需镜像状态，期限 2 秒，不在生产引入等待。最终 release 完整回归：exchange **932 通过、45 忽略**；engine **147 通过、7 忽略**。部署后另取完整 30 分钟同口径验收，最终实盘报告位于 hexbot 仓库 `docs/maker02_execution_publication_tail_20260927.md`，未以本基准代替实盘验收。
