# Durable maintenance recovery and causal cancellation timing

A lost split submission response followed by `batch nonce … does not match on-chain nonce …` previously became a definitive failure. That released the maintenance reserve and admitted another split with a fresh nonce. A typed ambiguous outcome now survives subsequent retry rejection. The existing maintenance owner persists operation ID, signer, wallet, nonce, request hash and deadline before POST; incomplete results retain the reservation and recover through the exact action payload or unique on-chain split proof. Identical retries retain the signed body. Nonce advancement alone never credits inventory. Confirmation/replay retains the existing exact-owner, idempotent seed delivery.

Cancellation signals carry a Copy causal source and local/exchange clocks through the bounded owner dispatch and pending completion. The background attempt recorder uses those clocks even for cancel-only callbacks. Old placement timestamps are never substituted. Unknown system/legacy origins remain null. `dispatched_ns` means submitting the HTTP future; HTTP first-write and authenticated private terminal are separate observation boundaries. The new cancellation observation stage is prepared before owner processing.

A physical HTTP socket publishes a monotone retirement generation when dropped. Existing execution owners inspect the current driver and request existing asynchronous, quarantined generation repair before another business request requires a handshake. Old socket retirement cannot invalidate a newer socket. There is still a race between the last check and a later disconnect; remote response latency remains outside this fix. Coinbase's first reconnect backoff falls from 200 to 25 ms, and only a nonempty snapshot resets it; the existing 30-second cap and index freshness protection remain.

## Ownership and backpressure review

- Maintenance intent mutates only on the existing account control owner. The existing bounded synchronous maintenance command and durability barrier run in cold maintenance workers, never on strategy callbacks. Legacy cold shared-account storage remains an incremental migration boundary; it is not a new quote admission authority.
- Cancellation metadata is owned by each signal/command/completion. Existing per-owner queues, FIFO/coalescing, overflow rejection and lossless private lifecycle routing are unchanged. No mutable cross-instance trigger cache or new queue is introduced.
- Socket retirement is a per-client driver publication consumed by its execution owner. Normal polling uses atomic state and an ArcSwap read guard. URL allocation, runtime task submission and network prewarming happen only on recovery, through the existing repair mechanism.
- No worker is added; existing CPU affinity and topology validation still apply. Audit formatting and histogram aggregation remain background work. The runtime still has pre-existing adapter allocations outside this change; this is not a claim of an entirely allocation-free system.

## Validation and performance boundaries

`cargo test --workspace --lib`: 1,655 passed, 91 existing ignored; no failures. Regression cases cover response loss followed by nonce conflict, late indexing, definite rejection after an ambiguous attempt, exact wallet/call matching, durable restart without a transaction ID, duplicate confirmation and old journal compatibility. Cancellation tests cover cancel-only callbacks, owner routing and FIFO duplicate coalescing; existing suites cover overflow, replay and instance isolation. HTTP tests cover idle close detection and late retirement of an old generation, with existing failed-prewarm/quarantine tests retained.

The deployment report will compare completed raw order attempts over actual live observation windows: N, median, nearest-rank P99/P999 and maximum for trigger→dispatch, trigger→first transport write, HTTP response, and private cancellation terminal, plus queue depth/high water/overflow. Before-deployment six-hour baseline: place N=59,546, median/P99/P999/max=0.230902/0.441808/0.490593/0.588953 ms. Cancellation baseline exact shared-callback join N=42,308 (71.814% coverage): 0.203749/0.378650/0.413014/0.530208 ms. The new direct-clock population is broader, so source/cohort differences must be reported. Market conditions make the live before/after comparison observational rather than a controlled causal estimate.

Absence of relayer/on-chain proof keeps a journaled operation pending; a crash between durable preparation and POST can require later operator reconciliation. No timeout alone releases that reserve.
