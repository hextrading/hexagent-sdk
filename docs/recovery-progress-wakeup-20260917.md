# Wake recovery retries after local order finality

On maker02 at 04:50:45 UTC, a peer reset affected public/private WebSockets and HTTP. A placement became unknown and its single-order query kept returning null. PR #262 recovered it on the first expiry audit at 04:55:00.110: all asset cancels succeeded, one complete market-filtered historical page contained no matching trade, and the lifecycle owner committed an authoritative zero-fill cancellation. Durable state retained the 16-share reservation before that proof and released it afterwards without losing audit fields.

The private-feed gate nevertheless stayed asserted until 04:55:17.922. Its open-order retry deadline had backed off to 30 seconds and did not observe that the expired order had already been resolved. This was an additional 17.8 seconds after local finality, distinct from the conservative wait for an active unknown order's market to expire.

During an existing retry wait, the socket task now checks the immutable execution snapshot at most once per 100 ms. If the preceding audit started with open orders and the published collection is now empty, it runs the complete audit again before the original deadline. The empty snapshot is only a retry hint. It does not release any order, reset the REST failure streak, accept incomplete history, advance a delivery certificate or clear the quoting gate. The audit, private FIFO recovery fence, lossless strategy delivery acknowledgements and reconnect-generation certificate remain mandatory.

The previous audit's nonempty flag and the next probe time are owned by the existing socket task. The probe deadline survives cancellation of the audit select arm by private WebSocket frames, preventing high private traffic from increasing the snapshot probe rate. An audit that already started empty receives no shortcut on failure; transport, routing or ledger errors therefore cannot cause an empty-snapshot retry loop. A newly disconnected generation discards the hints with its old recovery coordinator. Shutdown is checked before work and during eligible probe waits.

No new worker, queue, global mutable map or quote-path operation is introduced. Snapshot reads are confined to reconnect recovery. The existing bounded priority private lanes and their overflow/fence semantics are unchanged. HTTP and forwarding remain on the existing cold blocking runtime, and the socket keeps servicing private frames while the audit sleeps or runs.

Four new deterministic tests compare a drained-order retry at 100 ms with the old still-pending 30-second deadline, retain backoff for unchanged/already-empty failures, cancel and recreate the select arm 500 times while checking only once, and cover independent coordinators and shutdown. Account/engine/exchange suites passed 315/114/843 tests (1,272 total), including existing partial delivery, overflow, reconnect-generation, duplication and owner-routing cases.

The local debug microbenchmark measures dequeuing one ready synthetic private frame and selecting it while an audit timer is pending. Each mode processes 10,000 events through a precreated capacity-one lane; the new mode uses the actual immutable execution snapshot read when the bounded probe is due. Old median/P99/P999/max were 1.379/1.526/1.648/18.866 us; new values were 1.518/1.664/1.694/14.865 us. Both ended at depth 0, high water 1, overflow 0. This excludes network, JSON parsing, owner application and strategy delivery, and is not a production end-to-end improvement claim. The 100 ms bound concerns the retry hint under a running scheduler; the complete audit and delivery barriers can still take longer or fail closed.
